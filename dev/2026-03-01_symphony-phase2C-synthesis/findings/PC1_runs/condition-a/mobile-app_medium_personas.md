# mobile-app — medium — Brainstorming Persona Recommendations (Condition A)

## Recommended Personas

| Persona | Circle | Topic Cluster | Rationale |
|---|---|---|---|
| Devil's Advocate | Core | Feature Identification & Core Value | Core persona; directly warranted by the REQUEST's entrenched assumption that "simplification will improve retention" — the Analyst and Questioner volumes raise concerns like "feature popularity vs. feature value" and "what if the problem isn't feature count but poor information architecture?" DA surfaces whether the team is optimizing for the wrong thing before irreversible cuts. |
| Pragmatist | Core | Feature Identification & Core Value | Core persona; the REQUEST sets a hard constraint of "8 months of runway, team of 8, need to identify 3-4 core features" — Pragmatist anchors selection criteria in what's actually shippable given the runway, rather than theoretical value definitions. |
| Technical Expert | Inner | Feature Identification & Core Value | Strong Fit for technical/product topics. The Systems Thinker volume raises "technical debt accumulated to support 15 interdependent features" and "ghost code that still runs" — identifying which features are "excise-carefully" vs "delete-and-forget" requires implementation-specific knowledge of the codebase, data models, and shared infrastructure the REQUEST describes. |
| First Principles Thinker | Inner | Feature Identification & Core Value | Strong Fit for technical/product topics. The REQUEST's central question ("what represents our true core value?") is literally a first-principles question — the Questioner volume reframes it as "what if the problem isn't which features to keep, but which job users are hiring us to do?" FPT strips away accumulated assumptions to get to the fundamental value proposition. |
| Devil's Advocate | Core | User Communication & Retention Through Transition | Core persona; the REQUEST explicitly names "how do we communicate changes to existing users without triggering mass churn" as a top concern. DA pressure-tests communication strategies against the risk that "a 'clean relaunch' assumes users will give us a second chance after we've burned them" (Devil's Advocate volume). |
| Pragmatist | Core | User Communication & Retention Through Transition | Core persona; with 8% 30-day retention and 180K downloads, communication decisions have immediate, measurable consequences. Pragmatist focuses on feasible, minimum-viable communication mechanics (in-app messaging, email sequences) rather than idealized co-creation frameworks. |
| Audience Advocate | Inner | User Communication & Retention Through Transition | Strong Fit for user-facing/community topics. The REQUEST cites "small but passionate user bases for features we might cut" and user complaints about "too many notifications" — the Audience Advocate volume maps these stakeholder segments explicitly ("How might users experience a feature reduction—as simplification or as loss?"). Essential for understanding differential impact across user types. |
| Empath | Inner | User Communication & Retention Through Transition | Strong Fit for user-facing topics. The REQUEST's framing of "burned-out users" signals an emotional recovery dimension. |
| Devil's Advocate | Core | Team Morale & Organizational Impact | Core persona; the REQUEST flags that "the team feels burned out from maintaining too many features" and is "concerned about morale impact of 'killing our darlings.'" | Pragmatist | Core | Team Morale & Organizational Impact | Core persona; with 6 engineers, 1 designer, 1 PM on an 8-month runway, Pragmatist focuses on concrete morale interventions that fit team capacity — not abstract culture change. |
| Empath | Inner | Team Morale & Organizational Impact | Strong Fit for human-centered topics. The REQUEST explicitly cites "morale impact of 'killing our darlings'" — engineers who "built features that are now being deleted" experience real grief and identity loss. The Systems Thinker volume describes the self-reinforcing loop where "people feel ownership over 'their' features, they resist cuts" — Empath addresses the emotional core of this dynamic. |
| Storyteller | Inner | Team Morale & Organizational Impact | Strong Fit for lived-experience narratives. The Storyteller volume itself models what's needed: the "funeral scene when the team decides which features to cut" and "standup meeting six months from now" — concrete named scenarios of how morale actually shifts from "feature graveyard" to "shipping a polished experience" is exactly what this cluster needs. |
| Devil's Advocate | Core | Strategic Direction & Runway Decisions | Core persona; the REQUEST poses a fork ("simplify incrementally or relaunch from scratch") with massive consequences. DA stress-tests both paths — "the 8-month runway as a false constraint" (from Devil's Advocate volume) — and whether the relaunch premise itself is valid. |
| Pragmatist | Core | Strategic Direction & Runway Decisions | Core persona; strategic choices must survive the 8-month runway constraint. Pragmatist evaluates each path against cash burn, team capacity, and launch feasibility rather than strategic elegance. |
| Visionary | Inner | Strategic Direction & Runway Decisions | Strong Fit for strategic/vision topics. The REQUEST asks "what represents our true core value proposition" — a question that invites paradigm-level reframing. The Visionary volume reframes this as "what if fitness wasn't something you track, but something that emerges naturally..." — opening space for a simplified product that's not just "fewer features" but a fundamentally different category position. |
| Systems Thinker | Inner | Strategic Direction & Runway Decisions | Strong Fit for strategic topics. The REQUEST describes interlocking dynamics: 15 features, 180K downloads, 8% retention, team burnout, 8-month runway, technical debt, user trust. The Systems Thinker volume maps these exact feedback loops ("retention-burnout feedback loop," "erosion of goals pattern in incremental simplification"). Essential for choosing between incremental and clean-relaunch paths because the choice depends on which feedback loops dominate. |

## Selection Summary

- Total personas: 16 persona-slots across 4 topic clusters (4 per cluster × 4 clusters). Unique personas used: 8 (Devil's Advocate, Pragmatist, Technical Expert, First Principles Thinker, Audience Advocate, Empath, Storyteller, Visionary, Systems Thinker — with DA and Pragmatist appearing in every cluster as core).
- Circle distribution: Inner 8 slots (Technical Expert, First Principles Thinker, Audience Advocate, Empath×2, Storyteller, Visionary, Systems Thinker), Core 8 slots (DA×4, Pragmatist×4), Outer 0. No outer-ring personas selected — Accountant was considered for the runway/financial dimension but excluded because the financial analysis needed is already covered by Pragmatist + Systems Thinker (runway modeling, burn-rate scenarios), and there's no business-model or pricing-architecture work that would warrant Accountant's lens. Lawyer and Politician have no topical justification.
- Dominant topic drivers: (1) Feature identification requires a technical/product analytical lens (Technical Expert + FPT) because the REQUEST's "which 3-4 features" question is inseparable from codebase dependencies and first-principles value definition. (2) User communication is strongly human-centered — the REQUEST's explicit "trust," "churn," and "passionate niche users" language drives Audience Advocate + Empath. (3) Team morale is explicitly named in the REQUEST ("burned out," "killing our darlings") and calls for the human-centered triad (Empath + Storyteller). (4) The strategic incremental-vs-relaunch fork drives Visionary (paradigm reframing of "core value") plus Systems Thinker (the feedback loops that determine which path survives 8 months of runway).
