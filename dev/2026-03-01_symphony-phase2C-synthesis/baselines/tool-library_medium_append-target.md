## Per-Persona Internal Cluster Identification

### Provocateur (7 questions → 3 internal clusters)

Per the persona-selection guide, Provocateur has a "natural set point of ~7 questions with universal 3-cluster structure."

- **Cluster P-A: Frame inversion** (3 questions) — inverts the premise of "library exists to provide tools"
  - Q1: What if tools were designed to disappear after use? (disposal-as-design)
  - Q2: What if the library charged people to NOT borrow tools? (inverted payment)
  - Q6: What if the tool library's core service was refusing to lend tools? (non-lending)
- **Cluster P-B: Boundary/accountability redesign** (2 questions) — upends trust/verification structure
  - Q4: What if we designed the tool library to maximize theft and loss? (loss-as-signal)
  - Q5: What if borrowing a tool required zero verification but infinite accountability? (social transparency)
- **Cluster P-C: Structural/imaginative reframing** (2 questions) — challenges the physical-tool premise
  - Q3: Tool library only accepts tools that don't exist yet (hypothetical tools)
  - Q7: Each tool comes with an intentionally impossible condition for use (ritual structure)

Largest cluster: P-A (3). Next: P-B and P-C tied at 2; tiebreaker by source order → P-B first.

Largest clusters: V-A and V-B tied at 3. Tiebreaker by source order → V-A first.

## Integration Notes

Per D1's implementation description in the persona-selection-guide: "Append selected questions to the Phase 2C output under a persona-labeled section." The final Phase 2C output structure should be:

1. **Synthesized clusters** (30 questions across 11 clusters, per B3 Target) — each cluster labeled with its theme.
2. **Append section** (30 questions) — tagged by persona, in a distinct section of the output (or interleaved with clusters if the synthesis prompt design elects interleaving).

**Tagging style:** Each Append question should carry the `[Perspective: persona-name]` tag so the reader can distinguish Append-group distinctive voice from synthesized Q&A. D1 is silent on interleaved-vs-segregated presentation; the default assumed here is a **segregated Append section at the end** (per the persona-selection-guide's "directly appended" language), with clear persona-labels. SP1 may test variants of this integration.

**Cross-cluster tagging (optional):** Append questions can be secondarily tagged with the B1 thematic cluster they most closely relate to (column 2 in the table above), so synthesized clusters have a "see also" pointer to relevant Append content. Example: Cluster 10 (Ecosystem/Partnerships) has a "see also: Analogist Q1 (ecosystem), Q3 (immune), Q5 (guilds); Politician Q1 (informal power), Q2 (coalition sequencing), Q9 (opposition)" reference. This is a nice-to-have, not a D1 requirement.

**Provocateur treatment:** Provocateur questions inherently don't map cleanly to B1 thematic clusters (see B1 Orphan section). They are tagged as `[Perspective: Provocateur]` with no thematic-cluster cross-reference; the provocation itself is the payload. Consistent with the persona-selection-guide: "Absurd inversion + 'real insight' format is the entire value. Synthesizing strips the provocation."

**Politician integration is unusual:** Politician contributes 10 questions — the largest Append-persona contribution in this cell. These cluster into Governance (Cluster 8, 4 questions), Ecosystem (Cluster 10, 4 questions), Liability (Cluster 4, 2 questions), and cross-cutting into Space (Cluster 3, 1 question) and Access (Cluster 5, 1 question). The Politician's content is **organizational-political analysis** (coalition sequencing, veto players, legitimacy thresholds, founder lock) that would be stripped by synthesis. Readers should treat the Politician's 10 questions as the cell's governance/political-analysis layer, operating in parallel to the synthesized governance content in Cluster 8.
