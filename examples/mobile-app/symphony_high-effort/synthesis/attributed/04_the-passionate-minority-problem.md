## Synthesized Insights by Question

### Question 13: Passion as signal vs. switching cost, and what is owed to users who built habits

**Full question**: What is the right framework for deciding that a small but passionate user base for a particular feature does not represent the product's future — is passion a signal about value, or about switching cost? What analytical framework (weighing churn risk, acquisition value, technical cost, strategic alignment) decides whether a feature with, say, 500 highly active daily users justifies retention; what structural tests distinguish genuine early-adopter signal from a feature that simply rewards a different user type entirely; and what is owed to users who adapted their behavior around a feature now being cut (a person using the meditation guide for anxiety management, for example) — how would the team know whether discontinuing a feature would remove a meaningful support structure from someone's life versus merely inconveniencing a power user?

* **Run a cheap behavioral test that separates habit from value before deciding anything.** Six personas converge on the same move: do not theorize about whether passion is signal or switching cost, instrument it. Temporarily disable the feature for a slice of users (or pause it product-wide for two weeks) and watch whether those users stay engaged with the rest of the app or bounce entirely; pair that with an exit-style survey that asks the passionate cohort the one diagnostic question, "where would you go if this were gone?" If most name a free alternative they will migrate to, it is switching cost. If most say "nothing matches this," it is a signal worth heeding. This costs almost nothing (a feature flag plus an A/B test) and replaces intuition with data on a tight 8-month runway.
  * **2-week disable experiment with a 48-hour return threshold.** Run a 2-week experiment disabling the feature for 20% of users in the smallest passionate segments; if 70%+ return within 48 hours, passion is genuine switching cost, not core value. Costs almost nothing (feature flag + A/B test). *—The Pragmatist*
  * **Pause rather than remove, and measure the bounce.** Asking "why do you use this?" never yields honest answers because users have internalized the behavior; instead run a 2-week feature "pause" and measure whether those 500 users stay engaged with the rest of the app or bounce. Also gives users a glimpse of life without it, easing the psychological transition. *—The Devil's Advocate*
  * **Exit survey naming the destination.** Run a 30-day exit survey asking meditators specifically "where will you go when this is cut?" If 70% name a free app, it is switching cost; if 50% say "nothing matches this," it is signal. *—The Devil's Advocate*
  * **Behavioral archaeology over raw frequency.** Map not just frequency but contextual dependency: session duration inside the feature, which lapsed users returned specifically for it, support tickets calling it irreplaceable. If 40 of the 500 cite it in exit surveys as "why I open the app," that is switching cost. *—The Storyteller*

* **Distinguish feature-loyalty from app-loyalty by testing whether the value is portable.** Several personas note that daily use is not strategic fit, and that the cleanest tell is whether the underlying value survives the feature's removal. Ask the cohort directly whether they would stay if the same value arrived through a lighter vehicle (a weekly digest, a simplified in-core version). High "yes" means the value is portable and can be preserved cheaply; high "no" means the user is loyal to this exact feature and discontinuing it is the honest call. The same logic scales into a weighted scoring matrix so the decision is not driven by the loudest segment.
  * **Portability survey.** Ask the 500 most active users: "If we removed this but integrated the same content into a weekly digest email, would you stay?" 60%+ yes means value is portable; 80%+ no means real switching cost. A 10-minute, zero-cost survey. *—The Pragmatist*
  * **Weighted scoring matrix.** Rank features by (1) retention contribution (% of retained users who rely exclusively on it), (2) network/cascade effects, (3) technical debt to keep alive, (4) positioning clarity. 500 users where 10% use it as their *only* reason to open is a different case from 500 who use it alongside the core. *—The Devil's Advocate*
  * **Two-population structural test.** Run two separate conversations: one with heavy feature users ("what does this give you that you can't get elsewhere?") and one with the broader base ("what do you avoid or ignore?"). If the heavy users describe life-structure change and the broad base describes overwhelm, you have two different populations with different needs. *—The Audience Advocate*

* **Treat the ethical obligation to the anxiety user as real and bounded, not as a reason to keep an unprofitable feature forever.** Six personas insist the person using the meditation guide for anxiety management is owed more than churn management, because cutting a load-bearing coping structure without a bridge is genuine harm, not mere inconvenience. The shared resolution: the obligation is transparency, time, and a real hand-off (curated alternatives, partner onboarding, possibly a credit), not indefinite retention. The team can distinguish "support structure" from "power-user habit" by listening for outcome language ("how I manage stress") versus instrumental language ("everything in one place").
  * **A bounded obligation: transparency and time, not perpetual life-support.** The hardest frame to collapse to metrics. Mitigate with a 6-month wind-down, curated equivalent tools, possibly a one-time credit for a premium meditation app, and *no* claim of retention obligation beyond the window. *—The Devil's Advocate*
  * **Weight behavioral outcomes alongside usage.** A person using meditation for anxiety isn't optimizing engagement; they found a tool that works. The framework should weight "does discontinuing remove a meaningful coping structure?" The distinction between "this person will feel loss" and "this person optimized for this feature" should shape strategy more than DAU. *—The Audience Advocate*
  * **Negotiate genuine hand-offs before cutting.** If even 5-10% of meditation DAU are anxiety users, cutting without real integration pathways risks reputational and ethical damage; partner with 2-3 external platforms for discounted onboarding and give a hand-off, not a cliff. *—The Devil's Advocate*
  * **A "loyalty debt register."** Treat the 500 as emotional investors whose trust can't be liquidated by feature parity; document the exact ritual-space the feature occupied via diary data, session replays, and "what would you lose?" interviews, then make that debt visible in the relaunch narrative. *—The Visionary*
  * **Passion drowns out the data, and can mean desperation.** The 500 will *feel* like a bigger constituency because their attachment is vocal. Passion may signal latent market need *or* personal desperation ("I have nowhere else to turn"), which are completely different stories the team is likely to conflate. *—The Empath*

* **Reverse the burden of proof: a feature people cannot replicate elsewhere should demand a higher bar to cut, not a higher bar to keep.** A distinctive reframe surfaced by two personas: convention makes small features justify their survival, but irreplaceability flips that. Five hundred people who cannot easily reproduce a behavior elsewhere are a stronger reason for caution than a larger casual base. Ask "what would these people do instead?" before concluding the feature is niche.
  * **Higher justification to discontinue, not to retain.** A feature with 500 people who can't replicate the behavior elsewhere should demand higher justification for discontinuation than one with 2,000 casual users. *—The Audience Advocate*
  * **Switching cost as a gift, not a trap.** The cohort's switching cost proves they built workflows the feature genuinely serves; use it as a forcing function to identify the true job-to-be-done rather than chasing feature parity. *—The Constraint Flipper*

* **Don't let switching-cost guilt quietly reverse the roadmap.** A counter-pressure to the obligation theme: the guilt is legitimate as a feeling about human cost, but the least representative users must not be allowed to drive the product vision. Honor the guilt; do not let it reverse-engineer strategy.
  * **Guilt is real but must not override strategy.** The team will start rationalizing retention out of guilt about disrupting routines; that is a trap. Honor the guilt as a legitimate feeling, but don't let it reverse-engineer the roadmap. *—The Empath*
  * **Churn over the cut is itself a clarity signal.** Users who churn when the feature dies may be telling you it was only valuable *because* the main product was so confusing they hunted for side features; limited runway makes this a gift, since you can't chase every passionate segment. *—The Constraint Flipper*

* **A devoted niche may not be a feature to cut at all, but a different product hiding inside yours.** Two personas push the framing furthest: if the 500 are bound by anxiety management and mental-health community rather than fitness, you may have stumbled on a separate market segment with its own unit economics. The honest test is to ask what a product built purely for their revealed preferences would look like, and whether it is a fitness app or something else.
  * **Spin-out as a hypothesis test, not deprecation.** Inside the bloated app may live a category-defining niche product 500 people would pay for monthly; release a free minimal companion app, measure whether they migrate and spend, and you've turned deprecation into a product hypothesis test. *—The Visionary*
  * **Map willingness to pay and check for a second product.** Map the 500 on whether they'd pay standalone, accept ads, or churn if the fitness core is cut; if 80% would move to Calm and 70% won't pay for fitness, the devotion is real but not strategically relevant. Consider a spin-off or white-label offering instead. *—The Devil's Advocate*

### Question 14: The difference between leaving and grieving

**Full question**: For the small but passionate user bases attached to features being cut, what is the emotional texture of losing something they rely on — and is there a way to honor that feeling in how the relaunch is communicated, rather than just managing the churn risk?

* **Lead with honest reasoning about the cut; let acknowledgment follow rather than substitute for it.** All seven personas treat loss as grief, not churn, and agree the communication should name what is being lost. The productive tension they collectively resolve: empathy-first messaging ("we honor your feelings") reads as manipulation when the real driver is focus and sustainability, and can accelerate churn. The synthesis is a sequence: state the honest strategic reason ("we couldn't do meditation justice alongside fitness"), then sincerely acknowledge the loss, then offer concrete alternatives. Honesty about the trade-off, not optimistic spin, is what earns trust.
  * **Honesty before empathy, or the empathy rings hollow.** Passionate users see through "we honor your feelings" if the real message is cost-cutting; lead with the strategic reason, then acknowledge loss, then give alternatives. Saccharine messaging can accelerate churn. *—The Devil's Advocate*
  * **A deprecation narrative, not a shutdown.** Spend two weeks writing one honest story of *why* the feature is cut ("we couldn't do meditation justice"), email it 60 days out with a month of free partner access and a date. Grief is easier when it's expected and someone acknowledges it mattered. *—The Pragmatist*
  * **Let grief speak in the redesign announcement.** Replace sterile "streamlining to focus on core" with "we built meditation because we believed stress was the enemy; we were wrong, the enemy is fragmentation; here's what we're archiving and why." Users stay because they feel seen as people. *—The Visionary*
  * **Vulnerability as the brand.** Generic "excited about our new direction" rings hollow when people lose something real; honest trade-off talk ("we loved this too, here's why we're choosing this") is harder than spin but more persuasive. *—The Constraint Flipper*
  * **Build grieving space into the communication.** Explicitly acknowledge what's lost and why instead of smoothing it over: "We built features that helped some of you in ways that mattered. We're sorry those won't be here, and we understand if you move on." This may paradoxically reduce churn. *—The Empath*

* **Segment the goodbye by feature, because a lost relationship grieves differently than a lost routine or a lost utility.** Several personas note the relaunch cuts emotionally distinct features at once: a forum is a relationship and an identity, meditation is a daily ritual, recipes are a utility. Generic messaging fails all of them. Tailor the wind-down: forum users get export and a path to a Discord/Slack continuation; meditation users get integration guidance and partner trials; recipe users get a downloadable backup.
  * **Tailor communication per feature.** Forum users are losing a relationship and identity ("I was the running group leader"); meditation users are losing a routine. Segment the wind-down: conversation export and group migration for the forum, external-tool integration for meditation, recipe backups for recipes. Emotion is honored by specificity, not generality. *—The Devil's Advocate*
  * **Identify emotional routines, then witness them.** Week one, map which features carry emotional routines (meditation = morning ritual, coaching = accountability, forum = daily social connection); reach out to top users in each cohort and ask how they use it. The asking itself becomes a form of witnessing. *—The Storyteller*

* **Build a ritual goodbye that hands users their data and marks the ending as real.** A strong convergence: rather than a silent cutoff, give users a closing artifact. A final-login screen that thanks them by name, shows their accumulated minutes/streaks, and exports their data turns "we removed something" into "we exited responsibly." This is cheap (a couple of engineer-days) and converts resentful churn into goodwill toward the next product.
  * **A ritual goodbye screen with data export.** On last login, thank the user by name, show total meditation minutes, offer a PDF/CSV export. ~2 engineer-days; users who feel seen don't churn with resentment and may advocate for the next product. *—The Pragmatist*
  * **A structured discontinuation ceremony.** A final session to capture streaks, export journals, and create a personal artifact; 6 weeks notice with weekly "final meditations," and a closing "what did this teach you about yourself?" gratitude prompt captured as product folklore. *—The Visionary*
  * **Write goodbye letters, not apologies.** "This feature changed how you move. That matters. Here's what we learned that's going into the core." A ritual of respect that deepens loyalty among the users who stay. *—The Constraint Flipper*
  * **A transition period that feels like care.** Replace a hard cutoff with 60-day notice to export/migrate, a guide to external resources (including crisis resources if relevant), and a channel for invested users to feed the relaunch. *—The Audience Advocate*

* **Ask users not what to cut, but how they want to be told, and tailor to their emotional language.** A distinctive process insight: a short pre-announcement listening study about the *manner* of the goodbye surfaces different needs, lead time, honest reasons, or simply being understood, and lets the team match its messaging to each emotional language rather than running one-size-fits-all churn copy.
  * **The sentiment audit.** Spend a week asking passionate users "what would you need to hear to feel respected in this transition?" Some want lead time, some want the strategic reason, some need witnessed grief. Reflect those distinct languages in the plan. ~15 hours of research. *—The Storyteller*
  * **Tiered wind-down sized to stated need.** Ask the most-attached users how much lead time they need; a passionate minority may prefer a slow six-month fade (deprecated → unsupported → read-only → removed) over a hard cut, which also yields real data on whether they can live without it. *—The Devil's Advocate*

* **Accept that some passionate users should leave, and let them go with gratitude.** A single-persona reframe worth preserving: not every retained passionate user is a win. Some found a makeshift solution to a problem your product no longer addresses; releasing them cleanly, with thanks for being early believers, can be healthier than fighting to keep them in a product that no longer serves what they loved.
  * **Honor the people who leave instead of managing them.** The assumption that losing passionate users is a failure is off; some should leave because your product isn't really theirs. Let them go cleanly, with gratitude for being early believers. *—The Empath*
  * **Reframe churn as permission to grieve better.** Some users will leave; that's clarity, not failure. What you control is how you say goodbye. *—The Constraint Flipper*

### Question 15: The passionate minority's story

**Full question**: For each feature with a small but devoted user base, picture a user who would genuinely mourn its removal — someone whose fitness routine or social connection has been quietly shaped by that feature. What story would they tell about why it matters to them, and what would that story suggest about whether the value they've found could be preserved in a simpler, more focused form?

* **The stories reveal that users are loyal to a deeper need, not to the feature itself, and that need can often migrate into the simplified core.** This is the cluster's strongest convergence: all seven personas tell concrete user stories and arrive at the same conclusion. The meditation user is loyal to time-architecture and emotional regulation, not meditation; the forum user is loyal to belonging and witnessed struggle, not the forum; the meal-planner user is loyal to relief from decision fatigue, not meal-planning. The actionable move is to name the underlying need and ask whether a lighter core mechanic (pre-workout intention-setting, social accountability woven into the main flow, decisive in-flow nutrition guidance) can carry it forward without rebuilding the feature.
  * **Tell the story backwards to find the real feature.** "I rely on meditation for anxiety" → "what makes it trustworthy?" → "it's separate, simple, non-intrusive" → "I'm loyal to simplicity and safety as a design ethic." Deliver that quality across the whole core and the user feels understood rather than bereaved. *—The Constraint Flipper*
  * **The need is portable; the feature is the vehicle.** A meditation-for-anxiety user loses "a tool I've relied on," not a feature; the value might be preserved as accessible, just-in-time emotional regulation in the new core rather than a meditation module. *—The Audience Advocate*
  * **Time-architecture, not meditation.** "I use it at 5:47am, 13 minutes before I leave; 12-minute sessions give me 75 seconds to transition." The value is a precise psychological pocket; offer "pre-workout intention-setting" with the same timing logic and you preserve the insight without the feature. *—The Visionary*
  * **From "meditation tool" to "intention setting."** Marcus's story ("this app helps me show up as my best self") survives if the relaunch lets him set an intention before logging a workout; keep the meaning, change the vehicle. *—The Storyteller*
  * **Calm before the workout, missing from the core.** The meditation user resets a spiraling mind before the gym; their story says the core product is missing the emotional barrier to fitness, not a meditation feature. *—The Empath*
  * **Anxiety-aware design as a principle.** "I use meditation for anxiety" really means "the app was so overwhelming a quiet feature was my refuge"; the blueprint is progressive disclosure, fewer notifications, clarity of next steps across the core. *—The Constraint Flipper*

* **Social and community stories show that belonging and witnessed struggle, not the feature, are what retain people, and that this should be woven into the core rather than siloed.** Several personas tell forum/social/sleep-tracker stories where the real draw is not the nominal function but the feeling of not being alone. The recommendation is to make peer accountability and shared struggle foundational to the relaunched core (visible progress in the context of community witness, paired or small-group practice) rather than a separate feed users must seek out.
  * **The 3am companion.** Sarah's sleep tracker connected her to insomniacs worldwide; at 3am she "feels less alone." The value is witnessed struggle, not sleep data. Weave shared recovery and hard days into leaderboard and post-workout reflection so the relationship survives the feature. *—The Storyteller*
  * **"I came because someone cheered for me."** The social-feed user showed up for an audience, not the tracker; the relaunch may need social proof and accountability woven into the core, not siloed in a feed. *—The Empath*
  * **Belonging over fitness.** The forum regular ("the rest of the app is for Instagram-fitness people, but the forum is my people") would quit fitness apps entirely if cut; the question is whether the new core serves everyone fitness apps could serve. *—The Audience Advocate*
  * **Make loneliness impossible.** "I found 6 people rebuilding confidence after injury; every message was proof I wasn't alone." Design the core to be practiced in pairs or small groups; fitness as relational practice, not individual optimization. *—The Visionary*

* **Some stories expose unmet core need or compulsion, which changes whether you should preserve the value at all.** Two distinct single-persona reframes complicate the "preserve the need" optimism. One: some niche users reveal not niche taste but a desperate unmet core need (Celiac on a budget) that a small population depends on, so cutting simplifies the app but abandons constrained users. The other, darker reframe: some devotion is compulsion, not health, and cutting it may be a kindness the user won't recognize, which should be studied rather than reflexively preserved.
  * **The challenge-platform addict (compulsion, not love).** Someone checks leaderboards for external proof they're winning, feels shame, can't stop. Their devotion may be compulsive; cutting it might be a kindness. Don't assume intense engagement equals healthy product love. *—The Empath*
  * **Unmet core need, not niche taste.** A Celiac user on a limited budget built meal plans around what she can actually eat and afford; cutting it sends her "back to googling endlessly." This is the opposite of niche, a real constraint a small population is desperate for. *—The Audience Advocate*
  * **Economic disruption for community-as-business users.** Dev built a 40-client coaching income through the marketplace; the cut isn't a lost feature but a lost livelihood. Owe honesty plus a redirect to third-party platforms (Fittr, Trainerize) so his identity as a coach persists. *—The Storyteller*
  * **Secondary emotional value the team never designed for.** "I used meditation after my dad died... it taught me grief was schedulable and temporary." Features accrue meaning beyond their purpose; position daily practice as a space for emotional work and market to people in transition. *—The Visionary*

* **Turn stories into concrete, testable product decisions rather than abstract empathy.** A pragmatic throughline: the stories are only useful if they convert into specifics. Interview the top ~10 users per feature, capture verbatim language, then translate recurring patterns into minimal core mechanics (a "focus reset" timer instead of a meditation library) and use the same evidence to communicate the decision honestly.
  * **Document 3-4 real stories, then test feature-vs-app loyalty.** "Sarah logs in 6x/week, 2-3 PM, 5-minute sessions, 147-day streak." Ask "what would you lose?" — "I'd download Headspace" (switching) vs "I'd lose my work ritual" (behavioral) tells you whether the cut is a user problem or a product problem. ~3 days of work. *—The Pragmatist*
  * **Translate the pattern into an MVP-adjacent mechanic.** If users rely on meditation as a ritual timer between transitions, ship a "focus reset" (a bell and a 5-minute timer), one engineer, one week, no meditation library to maintain. *—The Pragmatist*
  * **Use stories to decide if a simplified form should survive.** If 7 of 10 say "I wind down after workouts," ship a post-workout breathing cool-down; if 7 say "this is my main meditation app," cut cleanly and don't build a hybrid that satisfies no one. *—The Pragmatist*
  * **Collect testimonials to feel the loss, not to market.** Gather 3-5 real "what would you do if this went away?" answers so the team *feels* what loss means; if answers involve anxiety, sleep, or respite, design the transition more carefully. *—The Audience Advocate*

### Question 16: Niche devotion as a product thesis

**Full question**: Features with small but passionate user bases are typically treated as a retention problem — "what do we do with these users when we cut the feature?" Flipped, they are evidence that a highly focused version of the app can generate intense loyalty. How might the team study the *relationship* between niche users and their favorite feature — the exact behavior, the language they use, the frequency — as a blueprint for what the relaunched core should feel like at its best?

* **Reverse-engineer the devotees' ritual, rhythm, and language and make that the design north star for the core.** All seven personas converge: the niche cohort is a living specification of what excellent, focused engagement looks like. Study session length, time of day, what happens before and after, repeat-vs-sample behavior, and the exact phrases users use ("my practice," "my escape," "my safe moment," "my people"). The recurring pattern, predictable, low-friction, low-notification, value-in-under-30-seconds, emotionally resonant, becomes the interaction model and even the language of the relaunched core: frame the workout as "show up for your practice," not "complete a workout."
  * **Map the rhythm of devotion.** Examine session length, time of day, sequence, repeat-vs-sample, weekend use. If every devotee opens at the same time for exactly 12 minutes then leaves, the feature is a psychological anchor; build the core to be the same, brief, ritualistic, timeboxed, an act of self-compassion, not a decision tree. *—The Visionary*
  * **Map the language of belonging.** "My practice" = identity, "my escape" = psychology, "my community" = belonging. If 60% use ownership/belonging language, people adopted it for agency and identity, not health; position the core as a personal practice users see themselves reflected in. *—The Visionary*
  * **Reverse-engineer the engagement rituals.** Log the top 20 devotees' time of day, session length, save-function use, retention arc; you may find they're there for a calm voice and a reminder (a simple utility) or for a meditating cohort (social stickiness). Use the data to decide which core features to optimize for depth vs breadth. *—The Devil's Advocate*
  * **Translate the design language directly.** Study what *doesn't* happen, no dings, no leaderboards, no FOMO, and inherit that restraint; if a user says "it's the only place I feel calm in the app," make the core inherit that calmness. *—The Constraint Flipper*
  * **Behavioral protocols as product language.** Study the exact phrases ("my wind-down," "my safe moment," "my people"); if they cluster around emotional safety, belonging, and just-in-time support, that's the community's voice telling you what the product should feel like. *—The Audience Advocate*
  * **Ritual consistency is the signal.** 47-second sessions, 6 days a week, returning at 7am and 7pm like clockwork; build that consistency into the core ("show up for your practice") using the devotees' own language and timing. *—The Storyteller*
  * **Calm clarity as a design target.** The devotees are beta-testing what an emotionally intelligent fitness product feels like; the blueprint isn't "add meditation," it's "design the core to feel psychologically safe, not overwhelming." *—The Empath*

* **Make obsessive intentional focus the explicit brand promise — proof that one thing done with restraint generates loyalty.** Several personas argue the devotion exists because the feature was trustworthy and unintrusive, not flashy, and that the team should promise users it will never again overwhelm them. Niche devotion becomes the proof of concept that a single, deeply executed core can earn the same intensity, and the relaunch should be built to *expand* that quality rather than treat it as an accident.
  * **Niche loyalty as the brand promise.** Those users appeared because the feature was trustworthy; promise "one core, done with obsessive intention, never again overwhelming." Use the relaunch to extend the same care into the mainstream. *—The Constraint Flipper*
  * **Devotion is a scaling hypothesis, not a retention problem.** 500 religious users prove people will open an app daily if it does one thing with clarity; ask "how do we expand what generates this devotion?" and make that pattern the north star. *—The Constraint Flipper*
  * **Build around the largest niche within the core.** Once the 3-4 core features are chosen, find which have their own passionate minorities and build for depth in one (capture 80% of the 300 most active fitness loggers) rather than breadth across demographics; the team is motivated building something genuinely loved. *—The Pragmatist*
  * **A devotion blueprint as design logic.** Build the three-core-feature app so each feature feels like its own app with its own pacing and ritual language, letting users become zealots of one thing; that niche devotion is the proof of product-market fit. *—The Visionary*

* **Guard against learning nothing — study the niche only if it can change the product thesis, not just confirm it.** A sharp single-persona caution that the others' optimism needs: flipping the frame is only worth it if it leads to a *different* thesis. The failure mode is studying the meditation users, discovering they want a contemplative wellness app, and then relaunching the same social-fitness app minus meditation, having learned nothing. The discipline: explicitly ask whether a product built purely on the niche's revealed preferences would reinforce or conflict with the proposed core, and quantify how much of the devotees' time is actually the niche feature.
  * **Don't build a second focused app that still misses.** Flipping the frame makes sense only if it yields a *different* thesis; otherwise you study the meditation users, learn they want contemplation and community, and relaunch the same app minus meditation. Ask "if we built purely for their revealed preferences, what would it look like, and does that conflict with our core?" *—The Devil's Advocate*
  * **Quantify niche-time vs app-time to spot a different product line.** If 80% of the 500's in-app time is meditation, they're meditation users who occasionally track workouts, a different product; if 50/50, the feature is genuinely complementary. ~3 days of data work. *—The Pragmatist*
  * **Distill each feature's single best capability and migrate that.** Ask "what one thing does this feature do better than everything else?" (meditation = session flow/resonance, marketplace = accountability, forum = witnessed belonging) and migrate that capability so the leaderboard becomes "witnessed achievement," the coach directory becomes "accountability partnership." *—The Storyteller*

* **Build the research loop forward: track whether the simplified core itself grows new niche devotion post-launch.** A single-persona forward-looking move: the passionate minority is not only a retro signal but a success metric for the relaunch. Commit to measuring, six months post-launch, whether new users arriving for the core develop daily devotion within it; emergent niche loyalty inside the refocused product proves you built something beloved rather than merely serviceable, and tells you whether to expand vertically or horizontally.
  * **A post-relaunch research protocol.** Track at 6 months whether 15% of new users become daily fitness loggers or 8% become challenge enthusiasts; emergent niche devotion inside the core proves genuine loyalty and signals whether the next expansion is vertical (deeper) or horizontal (a second feature). *—The Pragmatist*
  * **Co-authorship with departing devotees.** Pay 50-100 top users a small honorarium, run intimate group interviews, and use their language and values as the north star for the relaunch's tone and interaction design; their grief becomes co-creation. *—The Visionary*
