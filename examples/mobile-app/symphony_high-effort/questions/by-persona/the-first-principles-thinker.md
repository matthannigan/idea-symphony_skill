# Brainstorming Questions from The First Principles Thinker: Feature-Bloated Mobile App MVP Reset

---

## The Core Problem, Stripped Bare

1. **What problem does this app fundamentally exist to solve?**: Setting aside all 15 features and every analogy to competitor apps, what is the single irreducible human need this product was originally created to address — and how many of the current 15 features actually touch that need at all?

2. **What is a "fitness app" really for?**: If you had to explain the purpose of this product to someone who had never heard of fitness apps, wellness culture, or social media, what would you say? And does that explanation describe what the app currently does?

3. **What does a 47-second session actually mean?**: Before assuming that short sessions indicate failure or confusion, what behaviors would a session of that length be consistent with? What would a healthy 47-second session look like for a product that was working as intended — and does that description match anything the current app offers?

---

## Identifying Value from First Principles

4. **Which features pass the "would users build this themselves" test?**: For each of the 15 features, ask: if this feature were removed and users strongly wanted it back, would they find another app, build their own workaround, or simply stop caring? What does the answer reveal about which features address genuine needs versus manufactured ones?

5. **What does the 8% retention number actually measure?**: Retention is conventionally treated as a signal of product value, but at its core it measures whether users returned — not whether they were helped. What alternative interpretations of 8% 30-day retention exist, and how would each interpretation change which features to keep?

6. **What is the minimum intervention that produces a measurable fitness outcome for a user?**: Rather than asking which features users engage with, ask what the smallest possible product interaction would be that genuinely moves a user toward their fitness goal. Which existing features come closest to that minimum?

---

## The "From Scratch" Redesign Problem

7. **If the team were building this today with no legacy code and no existing users, what would they build?**: This is not a rhetorical question — if the current 6-engineer team started from a blank slate targeting users who described their needs as "overwhelming" and "don't know where to start," what would a v1 look like? How far does that imagined v1 differ from what you're left with after cutting to 3-4 features?

8. **What assumption about user behavior does each retained feature depend on?**: Every feature implies a belief about what users will do. For the 3-4 candidate core features, state the behavioral assumption each one rests on — and then ask whether the current data (180K downloads, 2% DAU/MAU, 47-second sessions) confirms or contradicts that assumption.

---

## Constraints as Design Parameters

9. **What would a product designed specifically for an 8-month runway look like?**: Rather than treating 8 months as a fear-inducing deadline, treat it as a design constraint: given that constraint, what is the simplest possible product that could demonstrate enough value to earn the next funding round? Does that product look like the simplified version you're already considering, or does it suggest something more radical?
